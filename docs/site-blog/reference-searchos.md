# 레퍼런스: Search OS (searchos.io) — meta-scan에 필요한 것만

2026-11-10 크롤(약 75개 URL). Search OS는 B2B GEO **운영 대행** 서비스(영업 폼·소개서·미팅 퍼널).
meta-scan은 **셀프 무료 분석 도구**라 퍼널은 다름. 콘텐츠·구조만 가져온다.

## 우리의 차별점

Search OS의 "무료 분석"은 전부 영업 문의 폼으로 연결됨 — 셀프 URL 체커가 없다.
→ meta-scan은 모든 글의 CTA가 **즉시 실행되는 URL 검사**. 이걸 글마다 전면에.

## 가져올 것

### 1. 용어사전 `/knowledge` (238개 용어: SEO 125 / GEO·AI 61 / 콘텐츠 52)
- 용어 1개 = 페이지 1개 → 롱테일 검색어를 가장 싸게 늘리는 방법
- 우리 버전: `/[lang]/glossary/<term>` — 정의 → 왜 중요한가 → 확인 방법 → "META_SCAN으로 검사" CTA
- 각 용어를 우리 검사 항목(robots.txt, llms.txt, OG, canonical, hreflang, 구조화 데이터…)과 1:1 연결

### 2. 허브-스포크 블로그
- 허브: "<주제>가 검색에 안 나올 때: N가지 확인" → 스포크 글들을 확인 순서로 재배열한 요약
- 스포크마다 허브로 역링크, 허브는 스포크 전부 링크
- 우리 허브 = 결과 화면 카드 단위: 기본 SEO / 색인 / 미리보기(OG) / AI 신호 / 콘텐츠 / 국제화 / Lighthouse

### 3. 글 템플릿 (순서)
1. 요약 2~3문단
2. 번호 붙은 H2 섹션 + 표(문제 / 기본값 / 영향 / 조치)
3. "핵심" 콜아웃
4. 단계별 확인 방법
5. FAQ (H3 질문형 → FAQPage 구조화 데이터)
6. 관련 글 (허브 포함)
7. 참고 문서 (Google Search Central, OpenAI 크롤러 문서 등 1차 출처)
8. CTA: URL 입력창 (우리는 바로 검사)
- 분량: 스포크 5~7분, 허브 9~10분

### 4. 다국어 블로그
- 같은 slug: `/ko/blog/x`, `/en/blog/x`
- 사이트맵에 hreflang alternates. 번역 없는 글은 해당 언어만.

### 5. 홈 문제 제기 문구 구조
- "AI가 못 읽으면 추천도 못 한다" 같은 한 줄 + 문제 3포인트 → 홈 보강 섹션 참고

### 6. 제3자 수치는 출처와 함께
- Ahrefs, Google Search Central 등 출처 명시한 통계만 사용

## 버릴 것 (그쪽의 실수 포함)

- 영업 퍼널(소개서·미팅·문의 폼), 고객 로고, 플랫폼별 랜딩(Cafe24·Shopify…) — 운영 대행 업종 전용
- 출처 없는 성과 수치("300× faster" 등) — 신뢰도 깎임
- 문서 title과 본문 H1 불일치
- 영어 글에서 일본어 글로 링크(언어 혼선)
- 빈 섹션 페이지 공개(`/analysis` 등 "No published content yet.")
- 글 안에 작성자 소개 없음 → 우리는 글마다 작성자 박스(페르소나) 넣기

## 나중에 검토

- 플랫폼별 글("카페24/아임웹 사이트가 검색에 안 나올 때") — 국내 수요 있음, 허브 몇 개 쌓인 뒤

## 덤: 우리 사이트 문제 발견

- `https://meta-scan.biz/llms.txt`가 200으로 **홈 HTML**을 반환 (soft 404). SEO/AEO 분석기가 자기 llms.txt가 가짜 → 실제 llms.txt 파일 추가 필요.
