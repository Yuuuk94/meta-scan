# 스페이싱 & 그리드 — meta-scan 디자인 시스템

> 커스텀 스페이싱 스케일은 없습니다 — Tailwind CSS v4 기본 스케일을 그대로 쓰고, 실제 코드에서
> 반복되는 값들만 이 문서에 정리했습니다(2026-08-13 기준 `grep` 집계).

## 기준 단위

Tailwind 기본값 그대로 **4px(0.25rem) 단위**입니다. `globals.css`는 spacing을 재정의하지
않습니다 — 재정의된 건 컬러/반경/그림자 토큰뿐입니다([`colors.md`](./colors.md) 참고). 단,
루트 `font-size`가 15px로 낮춰져 있어([`typography.md`](./typography.md) 참고) `rem` 기반
간격 값도 그 비율만큼 함께 줄어듭니다.

## 컨테이너 패턴

페이지 최상단 섹션은 거의 항상 다음 패턴을 씁니다:

```html
<section className="container mx-auto px-4 py-…">
```

`container`가 뷰포트에 따라 최대 너비를 잡고, `mx-auto`로 가운데 정렬, `px-4`(16px)로 좌우
여백을 줍니다. 이 조합이 8개 파일에서 반복됩니다 — 새 섹션을 추가할 때도 이 패턴을 그대로
따르세요.

## 콘텐츠 폭 (`max-w-*`)

섹션 안에서 텍스트/폼 블록의 폭을 다시 제한할 때 쓰는 값들:

| 클래스 | 빈도 | 용도 |
|---|---|---|
| `max-w-md` | 3 | 404/에러 화면처럼 짧은 안내 텍스트 + 버튼 블록 |
| `max-w-2xl` | 3 | 법적 문서 본문(개인정보처리방침/이용약관), URL 인풋 그룹 |
| `max-w-xl` | 2 | 스캔 진행 화면 본문 |
| `max-w-lg` | 2 | 에러/경고류 중간 크기 블록 |
| `max-w-3xl` | 2 | 히어로 타이틀, FAQ 섹션 |
| `max-w-sm` | 1 | 점수 프로그레스 바처럼 아주 좁은 블록 |
| `max-w-5xl` | 1 | "작동 방식" 3단계 그리드 전체 폭 |

**규칙**: 텍스트 위주 블록(안내문, 법적 문서)은 `max-w-md`~`max-w-2xl` 사이, 그리드/카드 레이아웃
전체는 `max-w-5xl`까지 허용합니다. 그 이상 넓히지 않습니다 — 한 줄이 너무 길어지는 걸 방지하기
위함입니다.

## 섹션 수직 리듬 (`py-*`)

페이지 레벨 섹션(히어로, 프로세스, FAQ 등)의 상하 padding:

| 클래스 | 실제 px (15px 루트 기준) | 사용처 |
|---|---|---|
| `py-24` | 360px | 메인 페이지 대형 섹션(히어로, 프로세스, FAQ, 법적 문서) — **가장 흔한 섹션 리듬** |
| `py-20` | 300px | 스캔 진행/에러 화면처럼 내용이 적은 중간 화면 |
| `py-16` | 240px | 404 페이지처럼 더 짧은 화면 |
| `py-8` | 120px | `/scan` 결과 페이지 컨테이너(탭/카드가 많아 섹션 자체 여백은 상대적으로 좁게) |

**규칙**: 콘텐츠가 적은 화면일수록 `py-*`를 크게 잡아 화면이 휑해 보이지 않게 하고, 콘텐츠 밀도가
높은 대시보드성 화면(`/scan`)은 상대적으로 좁게 잡습니다.

## 내부 간격 (`gap-*`, `space-y-*`)

카드/리스트 내부 요소 간격은 작은 값 위주입니다: `gap-1`(4px)·`gap-2`(8px)가 아이콘+텍스트
같은 인라인 그룹에, `gap-3`~`gap-4`(12~16px)가 카드 사이·폼 그룹에, `space-y-2`~`space-y-3`이
세로로 쌓인 리스트 항목 사이에 흔합니다. `space-y-10`처럼 큰 값은 법적 문서의 섹션 구분에만
예외적으로 씁니다.

## 반경 (Radius)

`--radius: 0.75rem`(12px)을 기준으로 `@theme inline`에서 파생됩니다:

| 토큰 | 계산식 | 실제 값(15px 루트 기준) |
|---|---|---|
| `--radius-sm` | `var(--radius) - 4px` | 8px |
| `--radius-md` | `var(--radius) - 2px` | 10px |
| `--radius-lg` | `var(--radius)` | 12px |
| `--radius-xl` | `var(--radius) + 4px` | 16px |

실제 사용 빈도: `rounded-full`(19, 아이콘 배지·점·프로그레스 바 끝단) > `rounded-md`(9, 기본
버튼/인풋) > `rounded-xl`(8, 카드·큰 버튼) > `rounded-lg`(6, 중간 카드) > `rounded-2xl`(2, 큰
아이콘 원형 배지). **규칙**: 텍스트/폼 요소는 `rounded-md`, 카드/컨테이너급은 `rounded-xl`,
점·아바타·프로그레스 바 끝은 `rounded-full` — 안쪽 요소일수록 반경이 작고 바깥 컨테이너일수록
큽니다(shadcn의 일반적인 규칙과 동일).

## 반응형 그리드

브레이크포인트는 `sm:`(13곳)과 `md:`(8곳) 두 개만 실질적으로 쓰입니다 — `lg:`/`xl:`은 현재
사용처가 없습니다. `md:`는 거의 항상 그리드 컬럼 수를 바꾸는 데 씁니다:

| 그리드 | 사용처 |
|---|---|
| `grid-cols-3` (`md:grid-cols-3`) | "작동 방식" 3단계, Lighthouse 점수 카드 3개 |
| `grid-cols-2` (`md:grid-cols-2`) | `/scan` 상세 탭의 인덱싱/콘텐츠 통계 2분할 |
| `grid-cols-4` (`md:grid-cols-4`) | AI 신호 카드 4분할(가로가 넓을 때만) |

모바일 기본값은 항상 1컬럼이고, `md:` 이상에서만 여러 컬럼으로 벌어집니다. `sm:`은 컬럼 수보다는
`flex-col` → `flex-row` 전환(예: 히어로의 URL 인풋 + 버튼 배치)에 주로 씁니다.
