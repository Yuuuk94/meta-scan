# Design System: meta-scan

> ADR-004(프리미엄 SaaS, 화이트/차콜+인디고)를 대체합니다. 결정 배경은
> [ADR-008](../adr/index.html#adr-008) 참고. 이 문서는 `meta-scan-front`의 실제 컴포넌트/토큰을
> 만들 때 그대로 참조하는 소스 오브 트루스입니다 — Google Stitch의 `DESIGN.md` 문서 정리 방식을
> 그대로 따르되(섹션 구성·서술 방식), 내용은 meta-scan이 확정한 "진 인덱스"(Zine Index) 톤입니다.

## 1. Visual Theme & Atmosphere

인쇄된 진단 보고서를 스캔한 듯한 편집/진(zine) 톤 — 신문·잡지 인덱스 페이지의 굵은 타이포와
얇은 룰 라인, 인쇄 여백을 웹으로 옮겨온 느낌. SaaS 대시보드의 카드+그림자+둥근 모서리 문법을
의도적으로 피하고, 대신 굵은 검정 룰(rule)과 채워진 색 블록으로 위계를 만듭니다. 무료·고트래픽
애드센스 도구라는 제품 성격에 맞게 화려하지 않지만, 진단 결과(pass/warning/fail/info)가 실제
인쇄물의 도장·색인 번호처럼 또렷하게 읽혀야 합니다.

- **밀도(Density)**: 6/10 — Daily App Balanced. 체크리스트 항목이 많아 정보 밀도는 있지만,
  굵은 룰 라인과 여백으로 숨 쉴 공간을 확보.
- **비대칭(Variance)**: 5/10 — 헤드라인·번호 라벨(01/02/03)에서는 편집 레이아웃 특유의 비대칭을
  쓰지만, 체크리스트 카드 그리드는 스캔 결과 비교가 목적이라 균등 그리드 유지.
- **모션(Motion)**: 2/10 — Static Restrained. 진단 도구라 화려한 모션은 배제, 아코디언
  펼침/접힘 정도의 최소 인터랙션만.

## 2. Color Palette & Roles

| 이름 | 값 | 역할 |
|---|---|---|
| **Paper White** | `#FAF6ED` | 기본 배경(웜 페이퍼 화이트) — 인쇄 용지 느낌, 순백 아님 |
| **Card Paper** | `#FFF9F0` / `#FFFFFF` | 카드·강조 섹션 배경(페이지보다 살짝 밝거나 순백) |
| **Ink** | `#141311` | 본문 텍스트, 룰 라인, 헤더/푸터 경계선 — 순수 검정(`#000`) 아님 |
| **Ink Secondary** | `#4A473F` | 서브 카피, 본문 설명 |
| **Ink Tertiary** | `#8A8577` | 메타 정보(타임스탬프, 라벨), 비활성 텍스트 |
| **Hairline** | `#E4DECB` / `#EFE9D8` | 얇은 구분선(1.5px) |
| **Brand Accent — Signal Orange** | `#FF4B1F` | 유일한 브랜드 액센트. CTA 배경, 헤드라인 하이라이트 블록, 링크, 강조 넘버링(01/02/03). 채도는 높지만 **판정 색과 절대 겹치지 않음**(아래 상태색 참고) |
| **Status · Pass** | `#3E7D4F` (배경 채움 시 텍스트 `#FAF6ED`) | 판정 배지 — 통과 |
| **Status · Warn** | `#E3A61E` (배경 채움 시 텍스트 `#141311`) | 판정 배지 — 경고 |
| **Status · Fail** | `#C81E3A` (배경 채움 시 텍스트 `#FAF6ED`) | 판정 배지 — 실패. **Brand Accent(오렌지)와 혼동되지 않도록 크림슨 계열로 분리** |
| **Status · Info** | `#6B6659` | 판정 배지 — 정보(감점 아님). 채움 없이 얇은 외곽선(`1.5px solid #D8D3C4`)만 — 유일하게 무게가 다른 배지 |

**규칙**: 액센트는 브랜드용(오렌지) 1개만 — 상태 4색(pass/warn/fail/info)은 브랜드 액센트가 아니라
"판정 시맨틱 색"으로 별도 관리합니다(장식이 아니라 의미). pass/warn/fail은 **동일한 무게의 채움
박스**로 표시(2026-08-18 결정 — 배지 3종의 시각적 위계를 동등하게), info만 아웃라인으로 낮은
무게. 순수 검정(`#000000`)·순백(`#FFFFFF`만 단독 배경으로) 금지 — 항상 웜톤 Ink/Paper 사용.

## 3. Typography Rules

- **Display/Headline**: `Big Shoulders Display`(700/800/900) — 굵고 압축된 컨덴스드 서체.
  숫자 라벨(01/02/03), 큰 헤드라인, 카드 제목에 사용. 트래킹은 타이트하게, 크기보다 굵기로
  위계를 만듭니다.
- **Body/UI**: `IBM Plex Sans`(400/500/600/700) — 본문, 라벨, 버튼, 배지 텍스트 전부.
- **Fallback stack**: `"Big Shoulders Display", sans-serif` / `"IBM Plex Sans", -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif`
- **금지**: Inter(범용 SaaS 폰트, 이번 톤과 안 맞음), 시스템 기본 서체를 헤드라인에 그대로 쓰는 것.
  일반 세리프(Times/Georgia/Garamond) 금지 — 편집 톤이지만 세리프 대신 컨덴스드 산세리프로
  "인쇄물 느낌"을 냄(세리프를 쓰면 오히려 전형적인 "에디토리얼 템플릿"처럼 보임).
- **숫자**: 체크리스트 데이터(단어 수, Lighthouse 점수 등)는 `Big Shoulders Display`의 굵은
  웨이트로 — 별도 모노스페이스는 쓰지 않음(진단 보고서이지 터미널이 아님).

## 4. Component Stylings

- **버튼(CTA)**: 채움 사각형, `#141311` 배경 + `#FAF6ED` 텍스트. **모서리 둥글림 없음**(sharp
  corners — 이 시스템 전체의 시그니처). 호버/액티브는 텍스트가 아니라 배경 톤 다운 정도로만.
  그림자·글로우 없음.
- **배지(판정)**: `pass`/`warn`/`fail`은 동일한 패딩(`3px 9px`)의 채움 사각형, 모서리 없음.
  `info`만 같은 크기의 얇은 외곽선(무게 낮춤). 배지 안 라벨은 `IBM Plex Sans` 700, 자간 넓게
  (`letter-spacing: .04em`).
- **카드**: 그림자 없음 — `1.5px solid #141311` 하드라인 테두리로만 경계를 만듭니다(인쇄
  박스 느낌). 카드 배경은 페이지보다 아주 살짝 밝거나 순백. 카드 그룹(그리드) 사이는 1px
  검정 룰로 셀을 구분(신문 지면의 컬럼 구분선처럼) — 갭 대신 룰 라인.
  체크리스트 항목이 많은 화면에서 카드를 남발하지 않고, 굵은 룰(`border-top: 4~5px solid
  #141311`)로 섹션을 구분하는 쪽을 우선.
- **입력 필드**: 라벨 없이 플레이스홀더만(URL 입력 하나뿐인 단순 폼) — `2px solid #141311`
  하드 테두리, 모서리 없음.
- **아코디언(FAQ)**: 펼친 항목은 배경을 `#FFF9F0`으로 살짝 띄우고, `+`/`−` 텍스트 토글만
  사용(아이콘 라이브러리 없이). 애니메이션 없이 즉시 전환.
- **번호 라벨**: 프로세스 스텝, FAQ, 개선 제안 등에서 `01`/`02`/`03` 형태의 큰 넘버링을
  `Big Shoulders Display` + 브랜드 액센트 색으로 — 이 시스템의 반복 모티프.

## 5. Layout Principles

- 그리드 우선(`display:grid` + `grid-template-columns: repeat(N, minmax(0,1fr))`), 퍼센트
  계산(`calc()`) 지양.
- 체크리스트 카드 그룹은 4열 균등 그리드(기본 SEO/Indexing/Content Stats/국제화·UX) — 스캔
  결과를 나란히 비교하는 화면이라 의도적으로 균등 그리드 유지(일반적인 "3열 동일 카드는
  금지" 같은 통칙보다, 이 제품의 "그룹별로 훑어보는" 목적이 우선).
- 컨테이너는 최대 폭 제한(데스크톱 1200px 프레임 기준, 실제 구현 시 `max-width` 컨테이너 +
  좌우 여백 56px).
- 헤더/푸터는 굵은 룰(헤더 하단 4px, 푸터 상단 1.5px)로 페이지 경계를 표시 — 그림자로 뜨는
  느낌 없음(플랫 인쇄물처럼 화면에 붙어 있음).
- 섹션 간 구분은 카드 그림자가 아니라 배경 톤 전환(`#FAF6ED` ↔ `#FFF9F0`) + 굵은 룰로.

## 6. Motion & Interaction

- 기본은 정지 상태 — 트랜지션은 아코디언 펼침/접힘, 버튼 배경 톤 변화 정도로 최소화.
- 스캔 진행 화면(`ProcessScreen`)의 진행 바/스텝 아이콘 전환만 예외적으로 `transform`/`opacity`
  기반의 짧은 트랜지션(150–200ms) 허용 — 실제 API 완료 이벤트에 반응하는 용도이지 장식용
  모션이 아님(ADR-003 참고).
- 스크롤 유도 화살표, 바운스 애니메이션, 커스텀 커서 등 장식성 모션은 전부 금지.

## 7. Anti-Patterns (금지 목록)

- 그라디언트 배경/텍스트, glassmorphism(backdrop-blur), 네온 글로우 섀도우 — 전부 금지
  (기존 ADR-004에서 이미 제거한 "AI 생성 티" 패턴을 이번 시스템에서도 유지)
- Inter 폰트 사용 금지(헤드라인/본문 전 영역)
- 순수 검정(`#000000`)·순수 회색 무채색 배경 금지 — 항상 웜톤 Ink/Paper 팔레트
- 카드에 둥근 모서리(`border-radius`) 사용 금지 — 이 시스템 전체에서 sharp corners만
- 이모지를 아이콘으로 사용 금지 — 필요하면 인라인 SVG(스트로크 기반)로, 없으면 텍스트/숫자
  라벨로 대체
- 상태 배지(pass/warn/fail) 중 하나만 채움 처리하고 나머지를 텍스트색으로만 표시하는 것
  금지 — 세 상태는 항상 동일한 시각적 무게(2026-08-18 결정)
- 브랜드 액센트(오렌지)를 실패(fail) 배지 색으로 재사용하는 것 금지 — 브랜드와 "실패" 판정이
  같은 색으로 겹치면 사용자가 오인함
- 가짜 통계·조작된 숫자(예: 푸터의 "SCANS: 247,891" 같은 것) 금지 — ADR-004에서 이미
  발견·제거한 패턴, 재발 금지
- 스크롤 유도 문구/화살표, "Elevate", "Seamless", "Next-Gen" 같은 AI 카피 클리셰 금지

## 8. 판정 배지 시맨틱 (이 제품 고유 — checks[] pass/warning/fail/info)

일반적인 디자인 시스템에는 없는, meta-scan 체크리스트 제품의 핵심 규칙입니다.

| 상태 | 시각 | 의미 | 톤 |
|---|---|---|---|
| `pass` | 채움 박스, `#3E7D4F` | 통과 | 안심 |
| `warning` | 채움 박스, `#E3A61E` | 경고 — 권장 사항 미충족 | 주의, 겁주지 않음 |
| `fail` | 채움 박스, `#C81E3A` | 실패 — 색인/크롤링에 실질적 영향 | 명확한 문제 |
| `info` | 얇은 외곽선만 | 있으면 좋은 신호(AEO/GEO 계열 다수) — 없어도 감점 아님 | 중립, 정보 제공 |

`info`가 시각적으로 가장 가벼운 이유: PRD 3.4절의 결정대로 "없다고 감점"이 아니라 "있으면
좋은 신호"를 무료 진단 도구 톤에 맞게 사용자를 겁주지 않고 전달하기 위함입니다.
