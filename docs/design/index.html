meta-scan 디자인 시스템

2026-08-13, packages/meta-scan-front의 시각적 디자인을 재작업하며 정립한 토큰·컴포넌트 규칙입니다. 아키텍처 페이지와는 다른 주제입니다 — 그쪽은 저장소 구조/스택/구현 패턴 같은 기술 설계를 다루고, 이 페이지는 색상·타이포·다크모드 같은 UI/UX 디자인 시스템을 다룹니다.

1. 개요 BEFORE / AFTER

작업 전 전 화면(헤더/푸터/히어로/프로세스/FAQ/스캔 진행화면//scan 결과 페이지)은 shadcn 기본 스캐폴드 토큰이 남아있는 채로, 실제 화면은 그 토큰을 쓰지 않고 요소마다 theme === "dark" ? "..." : "..." 삼항 연산자로 cyan→purple→pink 그라디언트, backdrop-blur, glow 섀도우를 직접 나열하고 있었습니다.

이전
  • 화면/카드마다 다른 그라디언트 색(cyan/purple/pink)
  • 점수·상태 색이 등급과 무관하게 장식적으로만 사용됨
  • @custom-variant dark가 주석 처리돼 components/ui/*가 OS 설정을 따르는 실제 버그
  • 푸터에 조작된 SCANS: 247,891 통계, 에러 화면이 엉뚱한 문구 재사용
이후
  • 화이트/차콜 중립 + 인디고 단일 포인트 컬러
  • 점수·상태는 success/warning/destructive로 고정 매핑
  • data-theme 쿠키 하나로 전체 화면 + components/ui/* 통일
  • 가짜 통계 제거, 에러 카피 수정

관련 커밋: style(front): replace AI-generated gradient theme with token-based design system, 배경/대안 검토는 ADR-004 참고.

2. 토큰 TOKENS

src/css/globals.css에 정의됩니다. 라이트는 :root, 다크는 :root[data-theme="dark"]에 같은 변수명으로 재정의하고, 화면 코드는 bg-primary/text-success처럼 토큰만 참조합니다 — 라이트/다크 값 자체를 알 필요가 없습니다. 전체 팔레트와 의미별 매핑표는 colors.md, 타이포그래피 스케일은 typography.md, 여백/그리드 스케일은 spacing.md에 정리돼 있습니다.

--elevation-sm/md/lg를 인디고 색조로 살짝 틴트해서(rgba(45, 39, 130, ...)) 순수 검정 그림자보다 배경과 어우러지게 하고, @theme inline에서 Tailwind의 shadow-sm/md/lg 유틸리티에 매핑했습니다.

--elevation-sm: 0 1px 2px rgba(30, 27, 75, 0.05);
--elevation-md: 0 6px 16px -4px rgba(45, 39, 130, 0.1);

3. 다크모드 배선 BUGFIX + SYSTEM

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

이전엔 이 선언이 주석 처리돼 있었습니다. components/ui/*(button/badge/tabs)는 이미 Tailwind dark: 클래스로 작성돼 있었는데, 이 변형이 없으면 Tailwind v4 기본값인 OS prefers-color-scheme을 따릅니다 — 브라우저 설정이 다크인데 앱의 테마 토글은 라이트인 경우 컴포넌트마다 다르게 보이는 실제 버그였습니다.

4. 사용 원칙 RULES

  • 포인트 컬러는 하나(인디고) — 화면마다/카드마다 다른 그라디언트 색을 쓰지 않습니다.
  • 점수·상태는 항상 success/warning/destructive로 매핑 — 임의 색이 아니라 고정 규칙을 따릅니다.
  • 그라디언트/blur/glow 금지 — bg-gradient-to-r, backdrop-blur-xl, shadow-*-500/20 같은 장식 효과를 다시 넣지 않습니다. 강조가 필요하면 --primary 색상 자체나 그림자 토큰을 씁니다.
  • 다크 분기는 dark: 변형으로, 삼항 연산자로 반복하지 않음 — theme === "dark" ? "bg-x" : "bg-y"를 요소마다 나열하는 대신 토큰 클래스 (bg-card, text-muted-foreground)를 쓰면 라이트/다크가 CSS 변수 레벨에서 자동으로 갈립니다. theme/lang prop 자체는 테마 토글 로직·카피 분기에 여전히 필요하므로 계속 내려가지만, 순수 스타일링 목적의 삼항 분기는 새로 만들지 않습니다.
다시 넣지 말 것 — from-cyan-*/from-purple-*/ from-pink-* 그라디언트, Sparkles 장식 아이콘, 조작된 통계 수치(예: SCANS: 247,891). 전부 이번 작업에서 제거된 패턴입니다.

5. 컴포넌트 패턴 COMPONENTS

components/ui/*(shadcn 골격: cva variant → cn() 클래스 병합 → data-slot)는 이번에 구조를 바꾸지 않았습니다 — 이미 토큰을 참조하고 있었고, 문제는 토큰 값과 dark: 배선 쪽이었기 때문입니다. 새 프리미티브를 추가할 때도 이 골격을 그대로 따르세요.

templates/*의 화면별 컴포넌트는 계속 theme/lang/ t를 props로 받는 구조를 유지하되(프롭 드릴링 자체는 이번 작업 범위 밖), 스타일링에 한해서만 토큰 + dark: 변형으로 옮겼습니다. 버튼/카드/인풋/모달 같은 프리미티브별 상세와 화면 레벨 합성 패턴(StatusBadge, ScoreCard, ProcessStep)은 components.md 참고.

영역바뀐 것안 바뀐 것
components/ui/*참조하는 토큰 값(팔레트)cva/cn/data-slot 골격, props 인터페이스
templates/*스타일링 클래스(토큰 + dark: 변형)theme/lang/t props drilling, 화살표 함수 vs function 선언 컨벤션

6. 다루지 않은 것 OUT OF SCOPE

  • 아이콘/모션/카피 톤 — Lucide 아이콘 전량 사용, 정적 트랜지션 등도 "AI 생성 티"의 일부로 지적될 수 있지만, 이번 라운드는 색상·그라디언트·다크모드 배선에 집중했습니다.
  • /scan 결과 데이터 — 여전히 Math.random() 목업입니다. 실데이터 연결(POST /api/v1/scan/analyze)은 docs/meta-scan-plus-prd.md/ADR-003 스코프이며 이번 디자인 작업과 분리해서 진행하기로 확정했습니다.
  • 완전 커스텀 루트 404 — /ko/asdf처럼 라우트 자체가 없는 경로는 여전히 Next.js 기본 404가 뜹니다. 이 저장소에 진짜 루트 app/layout.tsx가 없어서 (app/[lang]/layout.tsx가 사실상 루트 역할) 루트 app/not-found.tsx를 추가하려면 레이아웃 구조 자체를 바꿔야 합니다 — 별도 작업으로 분리했습니다.
